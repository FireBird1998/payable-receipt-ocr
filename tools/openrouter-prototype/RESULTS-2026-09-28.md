Verdict: direct image extraction works and measured API charges are small, but this incomplete synthetic sample does not establish a production replacement for local OCR.

The five completed 2.5 responses were all correct. Its sixth attempt failed and remains in the denominator; this is an availability failure, not an observed wrong amount. Twelve of sixteen planned vision calls were attempted. Both negative controls for each model remain untested. The app stopped after the HTTP 429 because that response had no billing information; no automatic retry was sent. Known charges total $0.00387825, with one additional unknown charge. The OpenRouter Activity page requires web sign-in, so that unknown charge could not be reconciled with account activity in this session. The account key itself worked for eleven successful responses.

## Running-cost interpretation

On these short synthetic bills, mean measured API cost was $0.000448625 for 3.1 and $0.00023730 for 2.5 (completed calls only for 2.5). Simple extrapolation gives about $0.45 and $0.24 per 1,000 similar calls, respectively. These are not measured prices for 1,000 real bills. Longer images, output length, failures/retries, provider pricing, credit purchase fees and taxes can change the totals.

Local OCR has no per-call vendor fee, but its deployment cost is not measured here. For an illustrative dedicated OCR server costing H dollars per month, the break-even volume ignoring all other costs is H divided by the measured LLM price per bill. At an assumed $10/month, this is about 22,291 bills/month for 3.1 or 42,141 for 2.5. This is a hypothetical cost calculation, not a server quote or a proven throughput claim. Device-side OCR or already-paid spare compute changes the economics substantially.

## Method and next decision

Existing eight synthetic INR fixtures; one call per selected engine per image; direct image-only extraction; no OCR text or expected labels supplied to models. Same prepared image bytes, fixed prompt, temperature 0, reasoning disabled, max 768 output tokens, provider fallback disabled. Successful vision responses identified Google as provider. Latency includes request/network wall time and preparation; local OCR timings came from the prior local smoke run, not a concurrent fixed-host qualification. p95 on six samples is simply their maximum.

Raw observations, usage and generation identifiers remain locally in ignored `output/openrouter-synthetic-2026-09-28/observations.json`. No key is in that export. No real bill images were transmitted. Eight fixtures cannot establish production accuracy or Hindi/real-world coverage.

Next: reconcile the failed call in OpenRouter Activity and check rate limits; finish the missing negatives and the failed 2.5 case in a separately labelled follow-up. Clarify that paid receipts also need their recorded transaction amount, then test any revised prompt separately. A broader real Indian bill comparison requires explicit corpus transmission approval. Keep the production OCR unchanged pending that evidence.
