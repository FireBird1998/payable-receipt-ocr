The big idea

Recognition and persistence are separate responsibilities

payable-receipt-ocr is a local Python module. An application may call it directly or through an adapter, but authentication, expense validation, and persistence remain the application's responsibility.

Consumer · your application

Expense application

Owns people, groups, expenses, authentication, UI, validation, and persistence.

  • Input: an authorized image and currency context
  • Review: the user edits or confirms the suggestion
  • Data: the application owns all persistence

Module · Python package

payable-receipt-ocr

Turns a local screenshot into ranked amount evidence and a confirmation-only suggestion.

  • Image: Pillow, NumPy, OpenCV
  • Reading: Tesseract 5 through pytesseract
  • Decision: Python rules, Decimal, JSON

Optional adapter · not included

Self-hosted HTTP adapter

Can expose the Python interface over HTTP without gaining permission to save expenses.

  • Input: authorized receipt image
  • Output: amount, currency, evidence, warnings
  • Guard: user confirms before app persistence
Important wording: this avoids paid and cloud generative-AI services, but it is not literally “AI-free.” Tesseract 5 uses an offline LSTM recognition engine. The important privacy property is that the package processes the receipt locally. Tesseract documents the LSTM engine.

The package accepts JPG, PNG, or WebP. Pillow fixes EXIF orientation and converts the image into a predictable RGB representation. No database record is created here.

Technology roles

Do not confuse the reader with the judge

Pillow + OpenCV prepare pixels

Pillow loads and orients the file. OpenCV converts, deskews, resizes, normalizes, and thresholds it. Neither decides which rupee value is the final payment.

Tesseract reads visible text

Tesseract is the OCR engine. pytesseract calls that executable from Python and returns text, geometry, and confidence. It may read several plausible numbers incorrectly.

Python interprets receipt meaning

Repository code identifies money, recognizes labels, groups agreement across passes, and ranks payment labels above fallback totals. Decimal keeps currency math exact.

The user authorizes the expense

requires_confirmation is always true. Even “strong” means “safe to suggest,” never “safe to silently save.” Caller-owned persistence belongs after confirmation, not before it.

Current versus future

Know which arrows exist

Exists now

Local command flow

image file → recognize(...) → Tesseract subprocesses → typed suggestion

Proposed after holdout

Product integration flow

application → optional adapter → Python package → suggestion → user confirmation → application persistence

The future service should be a suggestion service, not an expense-writing service. That narrow boundary contains OCR mistakes and preserves the calling application's authentication, validation, and database responsibilities. The package intentionally contains no HTTP server or database adapter.
